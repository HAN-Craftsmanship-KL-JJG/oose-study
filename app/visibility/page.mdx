# Visibility and class diagrams

## Access modifiers in Java

Visibility says which other code may use a class, an attribute or a method.
"No modifier" is a level of its own: package-private.
A package is a folder of classes with the same `package` line, such as `com.spotify.model`.

| Modifier                      | UML | Same class | Same package | Subclass in other package | Everywhere |
| ----------------------------- | --- | ---------- | ------------ | ------------------------- | ---------- |
| `public`                      | `+` | yes        | yes          | yes                       | yes        |
| `protected`                   | `#` | yes        | yes          | yes                       | no         |
| no modifier (package-private) | `~` | yes        | yes          | no                        | no         |
| `private`                     | `-` | yes        | no           | no                        | no         |

```plantuml
package "public: everywhere" <<Rectangle>> {
  package "protected: + subclasses in other packages" <<Rectangle>> {
    package "no modifier: same package" <<Rectangle>> {
      package "private: only the class itself" <<Rectangle>> {
        class Keeper
      }
    }
  }
}
```

```plantuml
package "nl.han.library.domain" {
  class Borrower <<no modifier>>
  class Library
}
package "nl.han.library.ui" {
  class LoanScreen
}
Library --> Borrower : can use
LoanScreen ..> Borrower : cannot see\n(compile error)
```

A top-level class can only be `public` or have no modifier.
`private` and `protected` do not compile there.
For a class that is visible only inside its package, write no modifier at all.

## Package-private in Java and C++

C++ has no packages.
Its closest match is a class in an anonymous namespace, which only its own file can use.

## From class diagram to code

Each line and its Java code are on [UML symbols](/uml-symbols).

Which code fits this association from `CashRegister` to `PaymentMethod`?

```plantuml
interface PaymentMethod {
  +pay(amount : double) : void
}
class CashRegister
class IDeal {
  +pay(amount : double) : void
}
class CreditCard {
  +pay(amount : double) : void
}
CashRegister --> PaymentMethod
PaymentMethod <|.. IDeal
PaymentMethod <|.. CreditCard
```

<Example
  name="visibility/cash-register-association"
  title="The association CashRegister → PaymentMethod in code: a field of the interface type, set through the constructor"
/>

Common mistakes:
`class CashRegister implements PaymentMethod` is a dashed line with a triangle.
`class CashRegister extends PaymentMethod` is a solid line with a triangle, and a class cannot extend an interface.
`new IDeal()` inside a method is a dependency on a concrete class, not an association.

<Compare>
<Side kind="good" title="Association with the interface">
```plantuml
interface PaymentMethod
CashRegister --> PaymentMethod
```

A field; works with every payment method.
</Side>
<Side kind="bad" title="Dependency on a concrete class">
```plantuml
CashRegister ..> IDeal : new IDeal()
```

No field; only iDEAL works.
</Side>
</Compare>
