# Java basics

## A class in a file

Each `.java` file holds one top-level `public` class, with the same name as the file.
`Keeper.java` holds `public class Keeper`.

```java
package nl.han.zoo.staff; // [!code highlight]

import java.util.List;
import nl.han.zoo.animals.Animal;

public class Keeper {
    private String name;            // field
    private List<Animal> animals;   // field

    public Keeper(String name) {    // constructor
        this.name = name;
    }

    public String getName() {       // method
        return name;
    }
}
```

## Packages

A package groups classes that belong together, like a folder.
The `package` line is the first line of the file, and the folder path follows it: `nl/han/zoo/staff/Keeper.java`.
The name is lower case and often starts with a reversed domain name, such as `nl.han`.

Two classes in the same package use each other without an `import`.
A class from another package needs an `import`, or its full name, such as `java.util.List`.
`import nl.han.zoo.animals.*;` imports every public class of that package, but not its sub-packages.
Classes from `java.lang`, such as `String` and `Math`, need no import.

A package is also a level of visibility: a class or member without a modifier is visible only inside its own package.

## Modules

A module groups packages, just as a package groups classes.
The file `module-info.java` in the root of the source folder describes the module.

```java
module nl.han.zoo {
    requires java.sql;                // this module uses the module java.sql
    exports nl.han.zoo.animals;       // other modules may use this package
}
```

Only exported packages are visible to other modules, even when their classes are `public`.
A package that is not exported stays inside the module.

```plantuml
package "module nl.han.zoo" as mzoo <<Node>> {
  package "nl.han.zoo.animals" as panimals #F9E7A8 {
    class Animal
  }
  package "nl.han.zoo.staff" as pstaff {
    class Keeper
  }
}
package "module nl.han.tickets" as mtickets <<Node>> {
  package "nl.han.tickets.ui" as pui {
    class TicketScreen
  }
}
TicketScreen ..> Animal : can use\n(exported)
TicketScreen ..> Keeper : cannot see\n(not exported)
```

| Level   | Groups   | Described by                  |
| ------- | -------- | ----------------------------- |
| Class   | Members  | `class Keeper { ... }`        |
| Package | Classes  | `package nl.han.zoo.staff;`   |
| Module  | Packages | `module-info.java`            |

## Fields, local variables and parameters

A field is a variable of the object: it lives as long as the object.
In UML a field is an attribute, or the end of an association line.
A local variable lives inside one method call, and a parameter is the input of a method.

```java
public class Enclosure {
    private int capacity;                     // field: part of the object

    public boolean hasRoom(int extra) {       // parameter: input of the method
        int total = countAnimals() + extra;   // local variable: gone after the call
        return total <= capacity;
    }
}
```

`this` is the object itself.
`this.name = name` copies the parameter `name` into the field `name`, which has the same name.

## Constructors

A constructor creates an object and gives its fields a start value.
It has the name of the class and no return type.

```java
public Keeper(String name) {
    this.name = name;
}

Keeper anna = new Keeper("Anna"); // new calls the constructor
```

Without a constructor, Java adds an empty one without parameters.
Once you write a constructor yourself, that empty one is gone.

## Methods

A method has a return type, a name and parameters.
`void` means the method returns nothing.

```java
public double foodPerDay(int days) { ... }
//     ^ return type  ^ name  ^ parameter
```

Overloading: two methods in one class with the same name and other parameters.
Java picks the method by the arguments of the call.

```java
public void feed(Animal animal) { ... }
public void feed(Animal animal, double kg) { ... }
```

A getter returns the value of a private field, and a setter changes it.
The setter can check the new value first.

## Access modifiers

| Modifier                      | UML | Visible in                                   |
| ----------------------------- | --- | -------------------------------------------- |
| `public`                      | `+` | every class                                  |
| `protected`                   | `#` | the same package and subclasses              |
| no modifier (package-private) | `~` | the same package                             |
| `private`                     | `-` | only the class itself                        |

## static

A `static` member belongs to the class, not to one object.
All objects share one copy, and you call it on the class name.
In UML a static member is underlined.

```java
public class Ticket {
    private static int sold = 0;   // one counter for all tickets
    private final int number;      // one number per ticket

    public Ticket() {
        sold++;
        number = sold;
    }

    public static int getSold() {  // Ticket.getSold()
        return sold;
    }
}
```

```plantuml
class Ticket {
  -{static} sold : int
  -number : int
  +Ticket()
  +{static} getSold() : int
}
```

A static method has no `this`, so it cannot use the fields of an object.
`main` is static: Java calls it before any object exists.

## final

`final` means "cannot change".

| On             | Meaning                                       |
| -------------- | --------------------------------------------- |
| A field        | Gets a value once, in its line or the constructor |
| A variable     | Gets a value once                             |
| A method       | A subclass cannot override it                 |
| A class        | No class can extend it, like `String`         |

A constant is `static final`, written in capitals: `public static final int MAX_ANIMALS = 20;`.

A `final` field that holds an object keeps the same object, but that object itself can still change.
A `final List<Animal>` cannot point to another list, but you can still add animals to it.

## Primitive types and references

A primitive type holds the value itself: `int`, `double`, `boolean`, `char`, `long`.
Every other type is a reference type: the variable points to an object.
`String`, `List<Animal>` and `Keeper` are reference types.

```java
Keeper a = new Keeper("Anna");
Keeper b = a;           // b points to the same object as a
b.setName("Bea");       // a.getName() is now "Bea" too
```

`==` on references asks "the same object?".
`equals()` asks "the same content?", so compare strings with `equals()`.

`null` means a reference points to no object.
Calling a method on `null` throws a `NullPointerException`.

## Lists and generics

An array has a fixed length: `Animal[] animals = new Animal[10];`.
A `List` grows and shrinks.

```java
private List<Animal> animals = new ArrayList<>();

animals.add(new Lion());
for (Animal animal : animals) {
    animal.makeSound();
}
```

`<Animal>` is a type parameter: the list holds only `Animal` objects.
Declare the field with the interface `List` and create it with the class `ArrayList`.
In UML, a `List<Animal>` field is an association with multiplicity `*` to `Animal`.

## extends and implements

`extends` makes a class a subclass of one other class.
`implements` makes a class fulfil one or more interfaces.

```java
public class Lion extends Animal implements Hunter, Comparable<Lion> { ... }
```

A class extends at most one class, but it can implement many interfaces.
An interface can extend other interfaces.

`super(...)` calls the constructor of the superclass, as the first line of a constructor.
`super.method()` calls the version of the superclass.

## abstract and interface

An `abstract` class cannot be used with `new`.
It can hold fields, constructors, normal methods and abstract methods.
An abstract method has no body: each concrete subclass must implement it.

```java
public abstract class Animal {
    private String name;

    public abstract String makeSound();   // no body

    public String getName() {             // normal method
        return name;
    }
}
```

An interface lists methods without code.
Its methods are `public` and `abstract` without you writing it, and it has no fields, only constants.
Since Java 8 an interface can also hold `default` methods with a body.

| Question                       | Abstract class | Interface |
| ------------------------------ | -------------- | --------- |
| Can it hold fields?            | yes            | only constants |
| Can it have a constructor?     | yes            | no        |
| How many can a class take?     | one            | many      |
| Keyword in the subclass        | `extends`      | `implements` |

In UML an abstract class and an abstract method are written in italics, or with `{abstract}`.

## @Override

Overriding: a subclass gives its own version of a method of its superclass or interface, with the same name and parameters.
`@Override` is an annotation that says "this method replaces an inherited method".

```java
public class Lion extends Animal {
    @Override // [!code highlight]
    public String makeSound() {
        return "Roar";
    }
}
```

The annotation is optional, but the compiler checks it.
With a typo, such as `makesound()`, the code no longer compiles, instead of silently adding a new method.

<Compare>
<Side kind="neutral" title="Overriding">
Same name and same parameters, in a subclass.
Java picks the method at run time, by the real object: polymorphism.
</Side>
<Side kind="neutral" title="Overloading">
Same name and other parameters, usually in one class.
Java picks the method when it compiles, by the arguments.
</Side>
</Compare>

An overriding method may not be less visible than the original: a `public` method stays `public`.
A `private`, `static` or `final` method cannot be overridden.

Other annotations you may see: `@Deprecated` (do not use this any more), `@FunctionalInterface` (an interface with one method) and `@Test` (a JUnit test).

## Exceptions

An exception stops the normal flow when something goes wrong.
`throw` starts it, and `try`/`catch` handles it.

```java
public void take(double kg) {
    if (kg > stockKg) {
        throw new IllegalArgumentException("Not enough food");
    }
    stockKg -= kg;
}

try {
    storage.take(50);
} catch (IllegalArgumentException e) {
    System.out.println(e.getMessage());
}
```

A checked exception, such as `IOException`, must be caught or named with `throws` in the method header.
An unchecked exception, a subclass of `RuntimeException`, needs neither.
